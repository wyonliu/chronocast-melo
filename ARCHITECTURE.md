## 核心数据流

```
用户输入 (txt/markdown)
    │
    ▼
┌───────────────┐
│ EpisodeInput  │ 解析主题、核心判断、情绪等
└───────┬───────┘
        │
        ▼
┌───────────────┐
│ ScriptGenerator│ AI编剧 → 生成对话文稿
│   (LLM API)   │
└───────┬───────┘
        │
        ▼
┌───────────────┐
│EpisodeScript  │ 包含：标题、内容、切片标记、金句
└───────┬───────┘
        │
        ├──▶ 保存为 Markdown (人工审阅)
        │
        ▼
┌───────────────┐
│TTSSynthesizer │ AI配音 → 生成双人语音
│   (TTS API)   │
└───────┬───────┘
        │
        ▼
┌───────────────┐
│ AudioMixer    │ 混音 → 合并+BGM+音效
└───────┬───────┘
        │
        ▼
┌───────────────┐
│ VideoGenerator│ 制片 → 生成视频
│  (MoviePy)    │
└───────┬───────┘
        │
        ├──▶ 完整视频 (16:9)
        ├──▶ 短视频切片 ×3 (9:16)
        └──▶ 图文卡片 ×5
                │
                ▼
        ┌───────────────┐
        │  PublishDispatcher  │ 分发到各平台
        └───────────────┘
```

## 模块职责

### 1. Writer（AI 编剧）

**文件**: `src/writer/`

- **generator.py**: 文稿生成器
  - 输入解析（EpisodeInput）
  - LLM 调用（Claude/DeepSeek/OpenAI）
  - 内容解析（提取切片标记、金句）
  
- **inspector.py**: 质检 Agent
  - 人设一致性检查
  - 对话自然度评估
  - 结构完整性验证
  - 输出评分和建议

**Prompt 工程**:
- `config/writer/system_prompt.md`: 核心编剧 Prompt
- `config/writer/inspector_prompt.md`: 质检 Prompt

### 2. Voice（AI 配音）

**文件**: `src/voice/`

- **synthesizer.py**: TTS 合成器
  - 文稿解析（提取对话行）
  - 多平台 TTS 支持（Fish/Minimax/ElevenLabs）
  - 声音克隆
  
- **mixer.py**: 混音器
  - 片段合并
  - 背景音乐融合
  - 响度标准化 (-16 LUFS)
  - 片头片尾添加

### 3. Studio（AI 制片）

**文件**: `src/studio/`

- **video.py**: 视频生成器
  - 完整视频（16:9 动态可视化风格）
  - 短视频切片（9:16 大字幕风格）
  - 角色头像 + 实时字幕 + 品牌元素

### 4. Publisher（自动发行）

**文件**: `src/publisher/`

- **dispatcher.py**: 分发调度器
  - 平台适配器（RSS/B站/公众号等）
  - 任务队列管理
  - 发布状态追踪

### 5. Analytics（数据监控）

**文件**: `src/analytics/`

- **collector.py**: 数据收集器
  - 各平台 API 对接
  - SQLite 数据存储
  - 指标计算
  
- **reporter.py**: AI 周报生成器
  - 数据分析
  - AI 洞察生成
  - Prompt 进化建议

### 6. Core（核心编排）

**文件**: `src/core/`

- **config.py**: 配置管理
- **pipeline.py**: 主流水线
  - 串联所有模块
  - 错误处理
  - 进度追踪

## 扩展性设计

### 添加新平台

1. 在 `src/publisher/dispatcher.py` 创建新的 PlatformPublisher 子类
2. 实现 `publish()` 和 `check_status()` 方法
3. 在 `PLATFORM_MAP` 中注册

### 更换 LLM/TTS

在 `config.yaml` 中切换即可：

```yaml
api_keys:
  # 切换 LLM
  deepseek:
    api_key: "xxx"  # 启用 DeepSeek
  anthropic:
    api_key: ""     # 留空则禁用
  
  # 切换 TTS
  fish_audio:
    api_key: "xxx"  # 启用 Fish Audio
```

### 定制视频风格

在 `src/studio/video.py` 中：
- 修改 `_create_scene_clip()`: 改变场景布局
- 修改 `_add_branding()`: 更换品牌元素
- 添加新的视频风格类

## 数据模型

### EpisodeInput（输入）
```python
theme: str              # 主题
core_judgments: List   # 核心判断
mood: str              # 情绪基调
reference: str         # 参考素材
melo_questions: List   # 麦洛想问的问题
```

### EpisodeScript（文稿）
```python
episode_number: int
title: str
content: str           # Markdown 格式
clips: List[ClipMarker]  # 切片标记
quotes: List[str]      # 金句
```

### EpisodeMetrics（指标）
```python
episode_number: int
date: str
podcast_plays: int
bili_views: int
short_views: int
# ... 各平台数据
```

## 错误处理策略

| 层级 | 策略 |
|------|------|
| LLM 调用失败 | 自动重试 2 次，失败后记录错误 |
| 质检不通过 | 根据模式决定：重试/暂停/继续 |
| TTS 合成失败 | 跳过该段，继续后续 |
| 视频生成失败 | 降级输出（仅音频+文稿） |
| 发布失败 | 记录到待发布队列，人工处理 |

## 成本优化

| 优化策略 | 效果 |
|----------|------|
| DeepSeek 替代 Claude | 成本降低 50%+ |
| 批量 TTS | 减少 API 调用次数 |
| 本地缓存 | 避免重复生成 |
| 文稿长度控制 | 直接影响 TTS 成本 |
